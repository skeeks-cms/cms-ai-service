# skeeks/cms-ai-service

Центральный сервис SkeekS AI в CRM поставщика: подключения установок, API v1, чаты, запуски и события, подтверждения, лимиты и учёт.

**Состояние:** внутренний пилот, не выпущен. Каталог `pilot/` — прототип оркестратора на Node.js, работающий на стенде; `src/` — PHP-часть пакета.

План и решения — [platform-plan, crm/ai-technical.md](https://github.com/skeeks-cms/platform-plan/blob/main/crm/ai-technical.md).

## Перезапуск пилота на Windows-стенде

Сервис `pilot/server.mjs` слушает `127.0.0.1:18764` и запускается с переменными окружения `SKEEKS_AI_*` (сервер исполнения, ключи, профиль Claude). Их значения не хранятся в репозитории. Чтобы перезапустить его после правки кода с тем же окружением, выполните на стенде:

```
python pilot/restart-stand.py
```

Скрипт (нужен `psutil`) находит процесс на порту, проверяет, что это `node.exe` с этим `server.mjs`, запоминает исполняемый файл, аргументы, папку и окружение, проверяет синтаксис, останавливает старый процесс и запускает новый в фоне. Затем шлёт пробный `POST /agent-turn` с ключом моста: ответ `503` «Отсутствует авторизация сотрудника» означает, что сервис работает. Значения переменных и ключ не выводятся. Если порт свободен, прежнего окружения нет — запуск с нуля требует заново задать переменные.

После перезапуска сервиса обновляется и код Codex-исполнителя (`skeeks-ai-runner/src/catalog-turn.mjs` передаётся на сервер исполнения при каждом шаге). Исполнитель Claude лежит копией на сервере исполнения и обновляется отдельно.
